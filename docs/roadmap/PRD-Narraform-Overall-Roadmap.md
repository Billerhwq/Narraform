# Narraform 内容自动化平台总体 PRD

**版本**：v1.0  
**日期**：2026-08-16  
**产品定位**：从用户资料出发，生成符合平台语境的内容，安全保存到平台草稿，并让发布反馈影响下一次创作。

## 1. 摘要

Narraform 当前已经完成内容创作 V1：支持小红书、知乎、公众号和通用文案，具备任务理解、事实隔离、策略推荐、统一内容操作、质量检查、自动保存与本地记录。

下一阶段不是继续堆“更多生成按钮”，而是把已有能力产品化，再依次接通素材、发布和反馈。最终闭环为：

```text
一句需求 / 截图 / 文档 / 网页
            ↓
可追溯的事实与内容策略
            ↓
平台化初稿与连续编辑
            ↓
发布包、平台草稿与送达回执
            ↓
表现快照、复盘建议与用户批准的经验
            └──────────────→ 下一次策略推荐
```

## 2. 用户与核心任务

### 目标用户

- 独立开发者、小团队产品负责人和内容运营。
- 有产品、观点、教程、活动或知识内容，但不熟悉每个平台表达方式的人。
- 需要内容效率，但不接受虚构、AI 模板味和无法验证的“自动发布成功”的人。

### 用户最少需要提供什么

必需：一句说明，例如“介绍 CodeLoop，它能读取仓库、规划修改、执行测试，写给独立开发者的小红书内容”。

可选：功能截图、产品文档、网页、已有文章、目标、受众、风格和限制。系统自动提取候选策略供选择，而不是要求用户填写复杂表单。没有截图或真实数据也可以写；系统只使用用户描述，不补造数字、客户和亲测经历。

## 3. 产品原则

1. **先完成内容，再展示系统**：界面只暴露用户需要做的决定，不展示 prompt、README、模型解析错误或内部 schema。
2. **事实与表达分离**：事实不足不等于不能宣传；可以基于用户描述表达价值，但不能补造证据。
3. **平台 Spec 是产品能力**：平台差异由版本化规范执行，不靠临时提示词。
4. **所有修改同一引擎**：首次生成、换标题、换正文、润色和自定义修改共享内容状态与质量门。
5. **草稿优先、回执为准**：自动化默认进入草稿箱，未经验证不显示成功。
6. **学习需用户批准**：表现数据只产生候选经验，不能静默修改以后所有生成。

## 5. 完整功能范围

### P0：闭环必需

- 自然语言任务理解和三策略推荐。
- 小红书、知乎回答/文章、公众号、通用文案 Spec。
- 富文本编辑、标题/正文联动操作、质量检查、自动保存、版本恢复。
- 图片/文件/网页素材及事实来源定位。
- 小红书、知乎、公众号发布包与草稿交付。
- 可验证交付回执、失败重试和手动导出。
- 发布指标手工录入、同类基线、复盘建议、经验批准。

### P1：闭环稳定后

- 视频与音频素材理解。
- 定时发布。
- 更多平台适配器。
- 内容模板、品牌表达包。
- 平台数据自动同步覆盖率提升。

### 明确不做

- 用户、团队、组织和工作空间系统。
- 平台账号管理中心；MVP 只在发布任务内临时登录。
- 自动互动、批量营销矩阵、无人确认的直接发布。
- 广告投放、收入归因和企业 BI。

## 6. 信息架构与界面原则

主导航只保留：`开始创作`、`内容`、`发布`、`复盘`。素材入口属于创作流程，不单独制造复杂资产中心。

| 页面 | 主要区域 | 用户主要动作 |
|---|---|---|
| 创作 | 对话上下文 + 文档画布 + 事实/检查栏 | 描述、选择策略、编辑、换一批、润色 |
| 素材理解 | 投递区 + 事实分组 + 来源预览 | 增删素材、纠正关键事实 |
| 发布 | 平台列表 + 字段适配 + 发布检查 | 确认并保存平台草稿 |
| 复盘 | 内容时间线 + 指标 + 建议 | 补数据、批准或忽略经验 |

视觉基线：Intercom 式友好对话感、Notion 式文档编辑感、腾讯式克制蓝白布局；组件以 Arco Design 为主，助手输入使用 Ant Design X Sender。禁止卡片套卡片、营销落地页式大标题和与任务无关的装饰。

## 7. 统一领域模型

```text
MaterialSet
  └─ EvidenceItem
       └─ FactSet
            ├─ TaskBrief
            └─ StrategySpec
                 └─ ContentState
                      ├─ OperationRequest
                      ├─ QualityReport
                      └─ PublishPackage
                           └─ DeliveryReceipt
                                └─ PerformanceSnapshot
                                     └─ RetrospectiveInsight
                                          └─ LearningRule
```

### 跨阶段不变量

- 每次内容改变都有 `contentRevision`。
- 每条公开主张可回到事实 ID；用户描述也属于合法来源类型。
- 发布包绑定不可变内容版本，后续编辑不静默改变已提交草稿。
- 表现快照绑定发布回执和内容版本。
- 学习规则绑定原始复盘建议，且需要用户批准。

## 8. 系统架构

```text
React Web
  ├─ Creation UI
  ├─ Material Review UI
  ├─ Delivery UI
  └─ Retrospective UI
        ↓ REST + SSE
Express Application API
  ├─ Task / Strategy Service
  ├─ Material Understanding Service
  ├─ Content Operation Service
  ├─ Quality Service
  ├─ Package / Delivery Service
  └─ Performance / Learning Service
        ↓
Adapters
  ├─ DeepSeek / Local Generator
  ├─ OCR / Vision
  ├─ XHS / Zhihu Browser Delivery
  ├─ WeChat Draft API
  └─ Metric Connectors
        ↓
Repository + File Storage + Job Queue
```

短期保留 Express 单体，但按模块边界组织。发布任务和素材分析进入持久任务队列，不能依赖单个 HTTP 请求生命周期。数据库可从当前 JSON 存储迁移至 SQLite，未来再替换 PostgreSQL；领域 ID 与 API 不依赖具体存储。

## 10. 非功能要求

### 性能

- 创作首屏交互时间小于 2.5 秒。
- 流式首字在模型响应后 1 秒内写入画布。
- 自动保存 P95 小于 800ms。
- 图片/文档逐项展示进度，不要求整组等待。

### 可靠性

- 内容操作与发布操作使用幂等键。
- 正式版本不保存半段流式结果。
- 单平台或单素材失败不扩大为整批失败。
- 所有外部适配器版本化，支持按平台熔断。

### 安全与隐私

- API 密钥只在服务端；日志脱敏。
- Cookie、token、上传文档正文不进入模型调试日志。
- 用户可删除素材、内容、回执与表现数据。
- 外部网页仅访问用户明确提供或批准的地址。

### 可观察性

记录操作 ID、任务耗时、重试次数、适配器版本、错误类别和成功验证方式，不记录完整私人内容。关键漏斗：开始任务 → 选策略 → 初稿完成 → 编辑完成 → 发布包通过 → 草稿已验证 → 补充表现 → 批准经验。

## 11. 测试策略

| 层级 | 覆盖 |
|---|---|
| 单元测试 | schema、字段权限、事实分类、平台映射、指标公式 |
| 契约测试 | 四份 Spec 的 CodeLoop 固定输入输出 |
| 集成测试 | 流式保存、解析任务、发布幂等、回执验证、规则注入 |
| E2E | 一句话创作；截图创作；三平台草稿；手工指标复盘 |
| 视觉回归 | 1440×960 桌面；390×844 移动关键创作页 |
| 故障演练 | 模型超时、OCR 不可用、登录过期、平台 DOM 变化、指标缺失 |

每个阶段只有在前一阶段契约测试继续通过时才允许合并。

## 12. 成功指标

### 用户结果

- 70% 新任务在不填写额外表单的情况下进入策略选择。
- 60% 初稿通过编辑或一次内容操作达到用户复制/发布意图。
- 90% 手动编辑在刷新后保持。
- 95% 显示“已送达”的草稿具备可信验证证据。
- 30% 有足够数据的内容产生至少一条用户保留的复盘建议。

### 质量护栏

- 未提供事实中新增数字、客户、排名、亲测经历的比例为 0。
- 换标题造成正文变化的比例为 0。
- `uncertain` 发布任务被显示为成功的比例为 0。
- 未经用户批准的学习建议影响新生成的比例为 0。

## 13. 里程碑与发布门槛

### M1：可持续创作

PR-01 合并。内容操作、流式编辑、自动保存、版本和事实检查均通过；旧接口仍可回滚。

### M2：低门槛输入

PR-02 合并。截图和文档来源可定位，无素材模式保持可用。

### M3：可信交付

PR-03 合并。至少小红书草稿链路在真实测试账号完成一次经过反查的送达；其他平台若适配器未稳定，必须保持导出而非伪成功。

### M4：可控学习

PR-04 合并。手工指标路径完整，样本不足保护和人工批准规则通过。

## 14. 风险与决策

| 风险 | 决策 |
|---|---|
| 浏览器发布易受页面变化影响 | 适配器隔离、版本探测、手动导出兜底 |
| 素材理解把观察当事实 | 证据分级和用户修正，禁止自动升级 |
| 质量规则阻止正常宣传 | 允许用户主张和非量化价值转写，只阻止补造证据 |
| 数据少导致错误优化 | 最低样本阈值、同类比较、相关性措辞、人工批准 |
| 当前前端单文件过大 | PR-01 先拆模块再叠加后续页面 |
| 初期没有账号体系 | 发布任务内临时登录，不引入账号中心 |

## 15. Definition of Done

总体闭环完成需同时满足：

1. 用户只输入一句话，或附加截图/文档，即可得到符合选定平台的内容。
2. 内容在换标题、换正文、润色和手动编辑中保持事实、平台规则和字段联动。
3. 至少一个真实平台草稿完成提交并通过远端反查验证。
4. 对该内容录入或同步表现数据，产生带基线和证据的复盘建议。
5. 用户批准建议后，新任务策略页明确显示该经验被采用，并允许取消。
6. 任一步失败都有可恢复路径，且不丢失上一步的正式结果。
